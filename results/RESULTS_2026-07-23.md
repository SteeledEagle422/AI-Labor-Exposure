## Inference (few-clusters corrections)

20 clusters, so the cluster-robust SE is the least trustworthy of the three.

| Method | p-value | Notes |
|--------|---------|-------|
| Cluster-robust (reference only) | ~0.000 | t = -4.69; unreliable at 20 clusters |
| Wild cluster bootstrap (primary) | **0.0086** | B=9,999, Rademacher |
| Randomization inference | **0.0678** | 472/500 valid reps; placebo mean -0.002, sd 0.192 |

**The two corrections disagree across the 5% line.** The wild bootstrap says
significant; permuting which sectors are "tech" says not, at 5%. With 4 treated
sectors, RI has very little power and its discreteness matters, so this is not
fatal on its own -- but the headline result is not robust to how you do
few-cluster inference, and that should be stated plainly rather than reporting
only the bootstrap.

## Threats to validity surfaced by THIS run

1. **The placebo test fails, and this is the headline problem.** Assigning a
   fake event date of 2021-09-01 -- more than a year before ChatGPT, and before
   the Fed hiking cycle -- still produces a large, significant "effect"
   (-0.204, t = -3.70). Roughly **half** the magnitude of the real estimate
   (-0.379) reproduces at a date where nothing happened. Something other than
   the AI-tool event is pushing tech postings down relative to control across
   this whole sample. The baseline DiD's -31.5% therefore **cannot be read as
   an AI effect**.

2. **A pre-existing drift shows up in `far_pre`** (-0.100, significant), which
   is the same story from the event-study side: divergence predates the event.

3. **The two inference methods straddle 5%** (0.0086 vs 0.068).

4. **Control-group definition moves the estimate by ~1.5x**, with no principled
   reason in this run to prefer one.

None of this is surprising, and none of it sinks the project -- it is precisely
the confound the triple-diff was designed to absorb. The problem is that the
triple-diff is the spec that did not run.

## What could not be run, and why

- **OEWS staffing patterns (step 4).** This blocks the exposure crosswalk and
  therefore both exposure-weighted specs. Two real bugs in the fetch script
  were found and fixed while chasing this (BLS moved `special.requests` ->
  `special-requests`, and the archive's readme workbook was being extracted
  instead of the estimates workbook). After those fixes the 32 MB file
  downloaded successfully once, but bls.gov then began returning
  `403 Access Denied` to further automated requests, and the corrected
  extraction never got a clean input. **This now needs a manual browser
  download** -- see the root README's manual step. Once
  `data/raw/oews/oesm24in4.zip` (or the extracted `.xlsx`) is in place, the
  script will pick it up with no further network access and specs 2 and 3 will
  run.
- **Google Trends (step 6).** Google returned 429 after two terms. Mechanism
  data only -- does not block any spec.
- **BLS CES was fetched successfully but nothing consumes it yet.** 720 rows
  sit in `data/raw/bls/`; no analysis script reads them. The confirmatory
  lower-frequency outcome described in the README is not actually implemented.

## Conclusion

**What can be claimed:** tech job postings fell sharply relative to control
groups after late 2022, the decline grows monotonically over the following ~24
weeks, and a synthetic control built on the pre-period tracks Software
Development well (pre-RMSE 0.040) before opening a -0.279 gap.

**What cannot be claimed:** that any of this is caused by LLM coding tools. The
placebo test at a null date recovers half the effect, so the baseline design is
measurably confounded -- exactly as the project's own README predicts. The
specs that would separate an AI effect from the 2022-23 rate-hike correction
(continuous-exposure DiD and triple-diff) are blocked on one manual file
download and have not produced a number.

**Next step:** download the OEWS file by hand, re-run, and fill in specs 2 and
3. Until then this run is a well-instrumented negative control, not a finding.
