## Headline specs -- the "coefficients move as you add rigor" table

Exposure = Eloundou beta (E1+E2), standardized; beta reads as the effect of a
1-SD increase in sector exposure.

| Spec | beta (log pts) | Cluster SE | t | Verdict |
|------|---------------|-----------|---|---------|
| 1. Baseline binary DiD | **-0.3789** | 0.0807 | -4.69 | large, significant -- **and confounded** |
| 2. Continuous-exposure DiD | **-0.0711** | 0.0509 | -1.40 | shrinks 5x, loses significance |
| 3. Triple-diff (main claim) | **+0.0101** | 0.0413 | **0.25** | **precisely zero** |

Spec 1: `post_chatgpt_launch`, n=5,300, 20 sectors. Specs 2-3: `post_copilot_ga`,
n=5,300, 20 sectors, 795 group x period cells.

**This is the central finding.** The naive tech-vs-non-tech comparison says tech
postings fell ~31.5%. Replacing the binary dummy with actual exposure scores cuts
that to a statistically insignificant -0.071. Adding the group x period fixed
effect -- which absorbs whatever hit all tech sectors in a given week, i.e. the
rate-hike correction -- drives it to **+0.010, indistinguishable from zero**.

The estimate does not merely lose significance; it lands on zero with a tight
standard error. The triple-diff retains **41.5%** of the raw treatment-variable
variation after absorbing FE, so this is a real estimate, not a collinearity
artifact.

## Inference (few-clusters corrections, on spec 1)

20 clusters, so the cluster-robust SE is the least trustworthy of the three.

| Method | p-value | Notes |
|--------|---------|-------|
| Cluster-robust (reference only) | ~0.000 | t = -4.69; unreliable at 20 clusters |
| Wild cluster bootstrap (primary) | **0.0086** | B=9,999, Rademacher |
| Randomization inference | **0.0678** | 472/500 valid reps; placebo mean -0.002, sd 0.192 |

The two corrections straddle the 5% line. With only 4 treated sectors, RI has
little power, so this is not fatal -- but even spec 1's significance is not
robust to how few-cluster inference is done.

## Threats to validity surfaced by THIS run

1. **The crosswalk structurally guts the intended identification -- the most
   important caveat here.** The triple-diff is supposed to compare Software
   Development against Data & Analytics *within* tech in the same week. But
   because sectors are mapped to NAICS codes and several Indeed sectors share
   the same codes, the within-group exposure variation is almost nonexistent
   in the treated group:

   | Group | SD of standardized exposure | distinct values |
   |-------|---------------------------|-----------------|
   | tech | **0.014** | 3 (of 4 sectors) |
   | stem_control | 0.127 | 2 (of 6 sectors) |
   | non_stem_control | **1.083** | 10 (of 10) |

   All five engineering/architecture sectors map to NAICS 5413 and therefore
   receive **identical** exposure scores. Within tech, the spread between the
   most- and least-exposed sector is 0.003 raw units. So the triple-diff's beta
   is identified almost entirely by within-**non-STEM** variation -- roughly 77x
   more dispersed than within-tech. **The null is real, but it is mostly not a
   test of the within-tech comparison the design describes.** It is closer to
   "do higher-exposure clerical sectors fall more than lower-exposure ones."

2. **The placebo test fails.** A fake event at 2021-09-01 -- before ChatGPT and
   before the Fed hikes -- still yields -0.204 (t = -3.70), about half the
   headline spec-1 magnitude. Combined with the significant `far_pre` bin, the
   binary design is measurably confounded by a pre-existing trend. This is a
   strike against spec 1, and part of why spec 3 exists.

3. **Spec 1's own significance straddles 5%** (bootstrap 0.0086 vs RI 0.068).

4. **Control-group definition moves spec 1 by ~1.5x.**

5. **Only 4 treated sectors and 20 clusters.** Everything here is low-powered.

## Conclusion

**The project's headline table is now complete, and it reports a null.** Going
from the naive binary DiD (-0.379, highly significant) to the continuous-exposure
DiD (-0.071, ns) to the triple-diff (+0.010, t=0.25), the estimated effect of AI
exposure on job postings collapses to zero. That collapse is exactly what the
design predicts if the 2022-23 decline in tech postings was driven by the
rate-hike correction rather than by LLM coding tools, and it holds across all
five exposure measures and both candidate event dates.

**What can be claimed:** within this panel, once you absorb whatever hit all tech
sectors in a given week, differential LLM exposure has no detectable additional
association with job-posting declines.

**What cannot be claimed:** that this is a well-powered test of the *within-tech*
mechanism. The crosswalk assigns near-identical exposure to all four tech
sectors, so the comparison the design is built around contributes almost no
identifying variation. A precise zero driven mostly by non-STEM sectors is not
the same as a precise zero for Software Development vs. Data & Analytics.

**Next step, and it is a substantive one:** the sector -> NAICS mapping is the
binding constraint on this design, not the data volume or the econometrics. Until
tech sectors can be assigned genuinely different exposure scores -- e.g. by
weighting Indeed's own occupation mix per sector instead of routing through
NAICS, where four distinct sectors collapse onto NAICS 5415 -- the triple-diff
cannot deliver the test it promises. Fixing that is worth more than any
additional robustness check.
